## Инцидент 2026-11-03 (вечер): установка 1.22-2 на роутер не прошла

Со слов пользователя: **opkg выдал ошибку при установке `.ipk`**, и в UI
Save & apply по-прежнему «тишина» (ни модалки, ни красного сообщения).

### Что известно достоверно

- Локальная проверка кода перед сборкой: harness в `%TMP%\xraymon-jstest\`
  (`node test.js <путь к config.js>`) — 8/8 PASS, синтаксис ok.
- `dist/luci-app-xray-monitor_1.22-2_all.ipk` собран на Windows (git-bash,
  GNU tar) — **первый ipk проекта, собранный не в CI**.
- Проверено распаковкой: `config.js` внутри ipk байт-в-байт равен рабочему
  дереву (то есть новый код в пакет попал).

### Найденная причина (высокая уверенность, текст ошибки opkg не снят)

Рабочее дерево на dev-машине CRLF-загрязнено: `core.autocrlf=true`,
`.gitattributes` в репозитории нет. `build-ipk.sh` пакует рабочее дерево
как есть (`cp -a`), поэтому в ipk попали файлы с `\r`:

| файл в ipk | CR-байтов |
|---|---|
| `CONTROL/postinst` | 37 |
| `CONTROL/prerm` | 17 |
| `CONTROL/postrm` | 7 |
| `usr/libexec/rpcd/xray-monitor` | 903 |
| `www/.../view/xray/config.js` | 301 |
| `usr/share/xray-monitor/xray-sub` | 0 |

BusyBox sh на роутере не выполняет постустановочные скрипты с CRLF →
opkg сообщает о провале установки. На роутере остался старый код →
«тишина при клике» — это исходный симптом плана (старый JS + кэш
браузера), а не поведение нового кода: новый JS до роутера не доехал.
Даже при успешной установке rpcd-бэкенд с 903 CR был бы сломан.

В git-коммит CRLF не попадает (autocrlf нормализует на checkin;
`git ls-files --eol` после staging — проверить, что index = lf).
