# F15: live balancer state + sticky balancer overrides

## What
- The Balancers tab now shows LIVE state per balancer (auto-refresh every
  10 s) next to the config editor: which outbound each balancer is using
  right now (`xray api bi` via the RoutingService), plus a per-balancer
  sticky-pin control (`xray api bo`).
- Sticky overrides ("pins"): pick a balancer + an outbound; the pin is
  applied LIVE (no restart, no config.json change) and persisted as a UCI
  `balancer_override` section (options `balancer`, `outbound`). Pinning a
  balancer that already has a pin replaces it (bo semantics: one override
  value per balancer, last write wins).
- Pins survive restarts two ways:
  - `post_restart_hooks` in xray-sub (previously an empty extension point)
    re-applies every persisted pin via bo after each config-writing
    command's restart+verify, under the same lock, output to stderr only,
    return value still ignored.
  - A "Re-apply overrides" button on the tab (rpcd
    `balancer_override_apply` -> `xray-sub overrides-apply`) restores pins
    after an EXTERNAL restart; the tab flags divergence between the saved
    pins (UCI) and the ones active on the running xray (bi).
- New rpcd methods (declared in `list` AND granted in the ACL):
  - `balancers_live` (read): bi snapshot + current overrides, merged
  - `balancer_override_set {balancer, outbound}` (write): bo + UCI upsert
  - `balancer_override_del {balancer}` (write): bo -r + drop UCI section
  - `balancer_override_apply` (write): re-apply all pins from UCI
- New `xray-sub` commands: `overrides-list` (read-only JSON of the pins),
  `overrides-apply` (mutation lock held; re-applies via bo).
- New ucode: `balance.uc` (pure module: bi mapping, divergence state
  machine, override validation, live snapshot assembly, stale-section
  filter) + `balance-cli.uc` (CLI: live / validate / applicable).

## bo/bi semantics relied on (xray-core v26.10.21, verified on the box)
- `bi -json <tag>` -> `{"balancer":{"override":{"target":...}|{},
  "principleTarget":{"tag":[...]}}}`. An unpinned balancer reports
  `"override": {}` (protojson drops the empty target). principleTarget is
  the strategy's current selection: leastPing/leastLoad -> the picked
  node(s) (what the tab shows as "using"), random/roundRobin -> the whole
  candidate set (those pick per connection; the tab says "any of: ...").
- `bo -b <bal> <outbound>` REPLACES the single override value of that
  balancer; `bo -b <bal> -r` clears it. Both fail (rc 1, "cannot find
  tag") for an unknown balancer. bo does NOT check that the outbound
  exists - the app validates membership against config.json first
  (balance-cli validate), otherwise the balancer would route into the void.
- The override table is in-memory state of the RUNNING xray only; a
  restart (any) drops it. UCI is the durable copy; hooks re-apply.

## Notes
- Timeout guard: every bi/bo call passes `-t 2` (xray's own api timeout),
  and balancers_live runs the per-balancer bi calls in parallel, so the
  ubus call is bounded by one call even with several balancers.
- Divergence wording: `missing` (UCI pin, none running - external
  restart), `drift` (both, different outbound), `unexpected` (running pin
  with no UCI record, e.g. pinned from the CLI). Computed in balance.uc,
  golden-tested.
- Stale pins (balancer removed from the config) are skipped by the
  re-apply (bo would reject them), counted as "skipped", and surfaced in
  the tab with a Remove button.
- No new Depends; POSIX sh / busybox only; UI strings via `_()`;
  23.05 LuCI APIs (`poll` for the 10 s refresh).

- tests/pipeline-scenario.sh: the xray stub now logs `api` calls (own

  overrides-apply command incl. its failing-bo path.
