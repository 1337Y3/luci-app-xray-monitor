# F13: end-to-end exit check ("does traffic actually FLOW?")

## The problem
The TCP probe says "reachable" for an exit that DPI (TSPU) then freezes after
the first ~16-20 KB: handshake fine, stream dead. Only pulling a real body
through the exit separates usable from dead.

## `xray-sub e2e [tag...]` (synchronous form, for cron)
- ONE tmpxray instance (contract B2) carries all checked exits: one socks
  inbound on 127.0.0.1 per tag, routing pinned per tag. Tags come from the new
  `e2e.uc tags` (outbounds whose settings name a server endpoint - the same
  probeable rule the rpcd probe list uses); explicit tags are validated against
  it. Exits in `probe_disabled` are NEVER dialled - they get a `skipped`
  verdict and no port at all.
- Per exit, at most 3 curls in flight overall (batch pool; busybox ash has no
  xargs -P), SAME user agent as the subscription fetch:
  1. the 204 URL -> TTFB (`%{time_starttransfer}`), `--max-time 10`
  2. the body URL -> bytes + speed, `--max-time` = 45 s per started MiB
     clamped to [45, 300]
- Verdicts (e2e.uc): `ok` (curl 0, HTTP 2xx/3xx, whole body: bytes >= expected
  when the URL is size-exact via `%d`, any nonzero body when it is not),
  `stalled` (bytes arrived, HTTP fine, transfer did not complete - curl rc 28
  or short read; the freeze signature), `fail` (connect/proxy error, HTTP
  >= 400, or zero body bytes), `skipped` (probe_disabled, never touched).
- The tmpxray TTL is sized for the whole run: ceil(n/3) x (10 + body_maxtime)
  + 75, clamped [120, 1800] - the watchdog cannot kill it mid-run but still
  reaps it if the script dies. The mini-lock (fd 4) is dropped right after
  start so other tmpxray users are not blocked for minutes.
- tmpxray is stopped explicitly at the end of a successful run AND from the
  EXIT trap `e2e_fini` on every path (success, failure, signal); the trap also
  removes the run marker and scratch dir. The batch pool children reset the
  traps and wait on their own pids only - a bare `wait` would sit out the TTL
  watching the watchdog.
- Results land incrementally in `/tmp/xray-monitor/e2e.json` (EXACTLY contract
  B3, no extra fields): skipped exits first, then one merge per finished
  batch, each merge atomic (.new + mv) so polling readers never see a torn
  file. `/tmp/xray-monitor/e2e.run` holds the runner pid while it is live -
  that flag lives OUTSIDE e2e.json so the contract shape stays exact for F18.
  A second `xray-sub e2e` while one runs fails fast (pid + cmdline guard).

## ucode helper `e2e.uc` (pure, golden-tested)
`verdict <r204> <rbody>` / `skipped` / `tags <config>` / `merge <e2e.json>
<run_ts> <tag> <record>` (prints the whole file; caller mv's it) / `status
<file> <0|1>` (file content + running flag) / `summary <file>` (one line per
exit + `# ok=N stalled=N fail=N skipped=N`).

## rpcd: `e2e_start` / `e2e_status` (declared in `list` AND the ACL)
- `e2e_start` never runs the check synchronously: it detaches
  `sh -c 'trap "" HUP; unset XRAYMON_NOWAIT; exec xray-sub e2e'` with output
  to `/tmp/xray-monitor/e2e.log`, exactly like `update_apply`. Returns
  `{"ok":true,"running":true,"msg":"..."}`; a run already in flight is
  reported, not restarted.
- `e2e_status` returns `{"running":bool,"ts":N,"results":{...}}` - e2e.json
  plus the flag from e2e.run (stale marker with a dead/reused pid is cleaned
  up; pid liveness is checked through the /proc cmdline guard).

## UCI options (defaults in files/etc/config/xray-monitor)
`e2e_cron` (0 - scheduled runs move real traffic and stay opt-in),
`e2e_schedule` (30 4 * * *), `e2e_url_204` (cp.cloudflare.com/generate_204),
`e2e_url_bytes` (speed.cloudflare.com/__down?bytes=%d), `e2e_bytes`
(1048576, clamped [1024, 104857600]). `cron-sync` manages the crontab line
alongside the fetch line: removed when e2e_cron=0, `e2e_schedule` when 1.

## UI (monitor.js Overview tab)
New E2E column with the last verdict per exit, colour-coded (ok green,
stalled amber, fail red, skipped grey) plus detail: TTFB/bytes/speed for ok,
"froze at N B" for stalled; tooltip carries the numbers and the timestamp.
"Run E2E check" button starts the run via `e2e_start`, disables itself while
running and polls `e2e_status` every 3 s until the run finishes. All strings
through `_()`.

## Tests
- `tests/run.sh`: golden verdicts for ok / stalled (timeout AND short read) /
  fail (connect, HTTP error, empty body) / ok-despite-204-timeout /
  expected=0, tag discovery, merge/status/summary shapes.
- `tests/pipeline-scenario.sh`: stubbed curl/netstat/xray-run drive the REAL
  runner end to end - verdicts per exit, mid-run progress (marker + skipped
  verdict visible before any connection), exactly the checked exits dialled
  with the subscription user agent, probe-disabled exit and non-exit outbound
  never dialled, tmpxray stopped and marker removed after the run, bad tag
  rejected, busy mini-lock -> every exit fails closed with zero connections,
  and the cron-sync line on/off.
