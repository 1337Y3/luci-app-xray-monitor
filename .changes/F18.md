# F18 — fetch subscriptions and self-update THROUGH xray

## What

For routers whose own uplink to the panel/GitHub is blocked while their xray
exits can reach it. Three new UCI options (defaults written into
`/etc/config/xray-monitor`, section `sub`):

- `fetch_via` — `direct` (default, today's behavior) | `proxy` (always through
  xray) | `auto` (try direct, retry a transport-level failure through xray) —
  for subscription fetches.
- `fetch_via_update` — same three values for the two SELF-UPDATE downloads;
  `0`/`direct` (default) = today. `opkg install` itself always stays local.
- `fetch_via_exit` — a specific outbound tag, or `auto` (default).

## Exit selection (`fetch_via_exit=auto`), in order

1. A concrete tag wins immediately, nothing else is consulted.
2. The freshest `/tmp/xray-monitor/e2e.json` (contract B3, written by F13):
   new `pickexit.uc` accepts it only when its top-level `ts` is within
   `E2E_MAX_AGE` (3600 s, shell constant) of now — a file from the future by
   more than 300 s is treated as clock skew and rejected too — and picks the
   result with `status: "ok"` and the highest `speed_bps`; ties keep document
   order. A fresh file with no ok result yields no winner either.
3. Fallback: the rpcd outbounds surface, `ubus call xray-monitor outbounds` —
   probes every endpoint (bare TCP, honors `probe_disabled`) and answers in
   config order; the FIRST outbound with `up=1` wins.
4. Nothing selectable → the fetch/update fails with today's honest statuses
   (`fetch-error` / download failure). In `proxy` mode there is NEVER a silent
   direct fallback.

## Mechanics

- Via-proxy = ONE tmpxray instance (contract B2, `do_tmpxray_start` called
  in-process, so no lock recursion) started lazily on first need, then
  `curl -s -D <hdr> -A <ua> --max-time 25 --socks5-hostname 127.0.0.1:<port>`:
  same UA (per-sub override included), same `--max-time`, same hdrfile flow —
  `subscription-userinfo` capture works on the proxy path. The mini-lock (fd 4)
  is released right after start so a minutes-long proxied fetch cannot block
  unrelated tmpxray use; `via_stop` runs on success, on failure and from the
  EXIT trap, and the self-update stops the instance BEFORE `opkg install`.
  The TTL watchdog stays as the last-resort backstop.
- Self-update: `update_downloads()` keeps today's two-step logic and messages
  (release asset → feed fallback); every curl goes through `via_curl`, which
  appends `--socks5-hostname` only while a port is up. The SHA256 gate
  (sidecar, Packages fallback, refuse on mismatch/absent) is untouched and the
  checksum fetches ride the same transport the .ipk came over. The detached
  `update_apply` runner in the rpcd backend is unchanged.
- Status surface: `xray-sub status` (→ `sub_get`/UI) gains `fetch_path` and
  `update_path` with the exact tokens `direct` / `via <tag>` /
  `direct, retried via <tag>` (auto), read from `$STATE/fetch_path` /
  `$STATE/update_path`; empty when no bytes moved. Greppable via
  `jsonfilter -e '@.fetch_path'`. The Subscriptions tab shows both as badges.

## Known scope lines (deliberate)

- `latest-version` (the update_check badge) stays direct: the task scoped the
  proxy to "the two downloads". On a fully blocked box `update_check` may
  report nothing while `update_apply` (proxied) still works.
- One exit per run, no second-best retry: if the chosen exit cannot even start
  its tmpxray, the run fails honestly (the e2e/probe surfaces pick the best
  known exit to begin with).
- tmpxray is replace-style: a proxied fetch that starts while an F13 e2e
  session is up stops that instance (one tmpxray at a time, per B2).

## Tests

- `tests/run.sh`: golden cases for `pickexit.uc` — best ok `speed_bps` wins
  (stalled/fail/skipped ignored), equal speeds keep document order, and
  refusals for stale / future-ts / no-ok / unparseable / absent e2e.json plus
  an explicit max-age argument.
- `tests/pipeline-scenario.sh`: ten new sandboxed cases with stubbed
  curl/ubus/tmpxray and a file-driven uci stub — fresh-e2e selection without
  consulting rpcd, stale-e2e → first-up fallback, nothing-selectable → honest
  `fetch-error` with zero curl calls, auto retry with identical UA/timeout/
  header capture, auto-with-direct-working never starting tmpxray, tmpxray
  start failure surfacing, proxied self-update (downloads proxied, opkg local,
  instance stopped before install), SHA mismatch refused (opkg never called),
  default self-update still direct, and auto self-update retry.

## How to verify on the router

```
git -c core.autocrlf=false archive --format=tar.gz -o /tmp/f18.tar.gz task/F18
scp /tmp/f18.tar.gz root@192.168.11.1:/tmp/   # extract to /tmp/t-F18/
sh tests/run.sh && XRAY=/usr/bin/xray sh tests/run.sh && sh tests/pipeline-scenario.sh
```
plus `sh build-ipk.sh /tmp/build-f18` from the same tree (local).
