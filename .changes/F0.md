# F0: xray API services + tmpxray

## enable-api: three services instead of one
`enable-api.uc` now ensures `HandlerService` (needed by `xray api ado/rmo`)
and `RoutingService` (needed by `xray api bi/bo`) alongside `StatsService`.
Still idempotent: prints `unchanged` (and `xray-sub enable-api` then skips the
restart) when all three are already in `api.services`; extra services the user
configured are preserved. CLI unchanged: `<config> <out> <port> [prefix ...]`.

## status: API services by config (no live probe)
rpcd `xray-monitor status` gains `api_services` (what `api.services` declares,
config order, deduped) and `api_missing` (required services absent). Derived
from the config file only, so polling stays cheap and works while xray is down.
The required list is `StatsService HandlerService RoutingService`, kept in sync
with `enable-api.uc` (duplicated as a shell constant in the rpcd backend).

## monitor.js banner
"Enable Stats API" became "Enable API services" and now shows whenever ANY of
the three services is missing from the config (listing them), or when stats
still answer nothing with everything configured. The button still calls
`enable_api`.

## xray-sub tmpxray (contract B2)
- `tmpxray start <tag>...` builds a standalone throwaway xray from the LIVE
  config via the new `tmpxray.uc` helper: one socks inbound on 127.0.0.1 per
  requested tag (random free ports, netstat-checked), routing pinned
  inboundTag -> outboundTag, `loglevel: none`, no api/stats/policy. Outbounds
  are copied verbatim - requested tags plus their dependency chain
  (`streamSettings.sockopt.dialerProxy`, `proxySettings.tag`); unrequested
  exits are not carried over. The candidate config is `xray -test`ed before
  start. Prints `{"pid":N,"ports":{"<tag>":port}}` once every port listens.
- `start` REPLACES a live instance (stop old, then spawn new) - one tmpxray at
  a time by design, so F13/F18 always know where to look.
- Lifetime is bounded by `XRAYMON_TMPXRAY_TTL` (default 120 s, must be >= 1):
  a detached (`setsid`) watchdog sleeps the TTL, TERM/KILLs xray, removes the
  temp dir, and deletes the state file only while it still records its own pid
  (a replacement instance can never be reaped by an old watchdog).
- `tmpxray stop` kills the process AND the watchdog, removes dir + state.
  Idempotent: prints `not running` (rc 0) when nothing is up.
- State: `/tmp/xray-monitor/tmpxray.json`
  `{"pid":N,"ports":{...},"dir":"/tmp/tmpxray.XXXXXX","ttl":N,"ts":N}` written
  atomically (`.new` + `mv`). Parallel start/stop serialize on the mini-lock
  `/var/lock/xray-monitor-tmpxray`, held only for the short critical section -
  never the config `LOCK`, so a tmpxray session cannot block fetch/apply.
- Nothing here writes the live config: outbounds are only read.

## tests
Golden cases for `enable-api.uc` (no api -> `changed`; StatsService-only ->
`changed`; fully enabled -> `unchanged` + byte-identical rewrite) and
`tmpxray.uc` (socks-per-tag config, dialerProxy/proxySettings chain copied,
unknown tag rejected), the latter `xray -test`ed when `XRAY` is set.
