# F16 — Backups tab and shared diff

## What

- New Backups tab (Services → Xray Monitor → Backups) listing all
  `config.json.bak.*` files with type, date, size and pinned state, and
  actions: View, Diff with current, Download, Pin/Unpin, Restore, Delete.
- New `xray-sub` commands: `backups-list`, `backups-get <name>`,
  `backups-delete <name>`, `backups-pin <name> <0|1>`,
  `backups-restore <name>`. Mutating commands run under the existing
  pipeline lock.
- New rpcd (ubus) methods: `backups_list`, `backups_get`, `backups_delete`,
  `backups_pin`, `backups_restore`, `config_diff` — each declared in the
  script's `list` section and granted in the ACL file (read: list/get/diff,
  write: delete/pin/restore; no other grants touched).
- New shared diff code:
  - `/usr/share/xray-monitor/jsondiff.uc` — ucode module with `canonsig()`
    (moved verbatim from `diff.uc`; its output is unchanged, goldens pass)
    and `paths_diff(a, b)` → `{added,removed,changed}` dot-paths.
  - `/usr/share/xray-monitor/jsondiff-cli.uc` — CLI wrapper for the module.
  - `www/luci-static/resources/xray-diff.js` — LuCI module with a pure-JS
    Myers unified line diff (`unifiedDiff`) and renderers
    (`renderUnified`, `renderSemantic`).
- `prune_backups` is now driven by `uci xray-monitor.sub.backup_keep`
  (default 5, `0` = keep all; shipped default written into
  `/etc/config/xray-monitor`). Pinned backups are never pruned.

## Decisions

- **Pin format**: a pinned backup is the same file renamed into
  `config.json.bak.pinned.<kind>.<ts>` (e.g. `config.json.bak.manual.X`
  ⇄ `config.json.bak.pinned.manual.X`). Single file, self-describing,
  lossless round-trip, no sidecar state to lose. `prune_backups` skips
  `*.pinned.*` unconditionally and only counts/deletes pipeline-shaped
  backups — a stray user-made `config.json.bak.something` is neither
  counted against the budget nor removed.
- **CLI wrapper file**: ucode modules must not have a shebang (`#!` is a
  syntax error in a module) and `export` is illegal in a main script, so
  one file cannot be both the module and the CLI. The module is
  `jsondiff.uc` (imported by `diff.uc` and the rpcd `config_diff`), and
  `jsondiff-cli.uc` is a three-line executable wrapper. CONTRACTS.md B4
  should be updated to name `jsondiff-cli.uc` as the CLI entry point.
- **config_diff direction**: `paths_diff(current, backup)` — `added` is
  what a restore would add, `removed` what it would drop. The Backups tab
  phrases it exactly that way, and the line diff uses the same direction
  (`-` = only in current, `+` = only in backup).
- **Restore** goes through the write pipeline: `xray -test` of the backup
  content happens *before* anything is touched, the current config is
  backed up as a new `manual` backup, then the normal
  test-install-verify-roll-back path runs, followed by pruning.
- **Download** uses `backups_get` + a client-side Blob URL (works with the
  existing rpcd plumbing; no new endpoint needed).

## Security

The client only ever sends a backup basename. Both `backup_path()` in
`xray-sub` and `backup_check()` in the rpcd script enforce: strict charset
(`[A-Za-z0-9._-]` only), membership in the real `ls -t` backup listing,
and the path is rebuilt server-side from the config file's directory.
Traversal (`../`), spaces, and unknown names are rejected by both layers
(defense in depth). Verified read-only against live data; destructive
paths verified in a sandbox only.
